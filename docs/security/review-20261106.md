# Buena Onda security review — 2026-11-06

Source changes are implemented on `security/review-20261106`, based on `304e821`. Production deployment, database migration, environment configuration and hosted verification remain separate rollout steps. This report describes verified code/schema findings; it does not claim that the production database currently has every legacy policy present in the repository.

Final local validation (Node 24.14.0, Windows, Next.js 15.5.29):

- Full suite after final dependency changes: **269/269 passed**, zero failures or skips (`node --import tsx --test --test-concurrency=2 "tests/**/*.test.ts"`). Includes standalone page guards, actual PostgreSQL role/policy tests, payment integrity/replay handling and draft-title privacy.
- `npm run build`: **passed**, including TypeScript validation and all 53 static pages. Existing image/performance and hook-dependency lint warnings remain; no lint errors. The framework upgrade required async request APIs, a Node runtime for the statically generated era page, and a Next Link for the home navigation.
- Local production server: **9/9 security HTTP checks passed** (`node scripts/security-http-check.mjs`). Unauthorized admin access, including a middleware-bypass header attempt, remains denied; intake requires authorization; payment creation via GET is refused; malformed/oversized bodies are rejected; security headers and no-store protections are present.
- Four additional HTTP checks returned 200 for `/`, `/cruise`, `/cruise/receiver` and `/studio/login`, with expected framing/CSP headers. The login response is private/no-store. This verifies HTTP behavior, not physical Cast playback.
- Online production dependency audit: **zero findings**. Full audit retains **two high entries for one advisory in the local IMG.LY worker**, with no safe compatible upstream fix. Native image/SDK/email compatibility checks passed. See [dependency remediation and residual risk](dependencies-20261106.md).
- The three first-party public HTML entrypoints had no reproducible query/hash/storage-to-script execution path. Generated third-party game bundles were excluded from this DOM review.
- Tracked-source scan inventoried 3,056 files and scanned 1,511 text/source/assets (61.7 MB). No recognizable private keys, provider secret tokens, credential URLs or JWTs were found. Generic secret-assignment matches were test fixtures. No credential-bearing `.npmrc` or tracked real `.env`/private-key files were found. A targeted environment/key history check found no exposure; this was not an exhaustive scan of every historical blob. One public bundled source map contains source code but no detected secrets.

Rollout order:

1. Review the tested changes and residual local-tool advisory. Next.js was updated to the vendor's [15.5.29 security release](https://github.com/vercel/next.js/releases/tag/v15.5.29). Supabase and Vercel integrations were discovered but are not connected in this session; live policy/configuration changes and deployment have not been performed.
2. Inspect the live Supabase schema/policies and take a schema backup. Apply `supabase/migrations/20261106120000_security_access_boundaries.sql` after existing schema migrations. It changes access controls, not stored rows; optional absent tables are skipped. Verify public published content, draft isolation, denied customer reads, service-role writes and public media playback. Keep these controls when restoring service; do not restore broad public write grants as a rollback shortcut.
3. Configure strong `STUDIO_PASSWORD`, `CRON_SECRET`, `TELEGRAM_CHAT_ID` and random `TELEGRAM_WEBHOOK_SECRET` values through the hosting secret store. Keep Supabase, Stripe, email and storage secrets server-only. Register the Telegram webhook with the same secret using `scripts/register-telegram-webhook.mjs`; coordinate registration and application rollout to avoid failed deliveries. Never put values in this report or commit them.
4. Add distributed edge/WAF limits for `/studio/auth/start`, paid/provider-backed intake, contact/newsletter/notification/reservation forms, checkout creation and public Avenue metrics/claims. Exclude authenticated webhook delivery from generic browser challenges. Existing in-memory limits reset with server instances and are not a distributed brute-force or cost-abuse defense.
5. Deploy a preview with appropriate test services, then the approved production build. Verify login/logout, unauthenticated and cross-origin denial, private no-store headers, checkout and signed webhook delivery, uploads with explicit Content-Type, public pages, media and Cast. Use test payments and avoid real customer writes during verification.

Scope and limits: source/configuration review, focused API/auth/upload regressions, local PostgreSQL policy execution and tracked text secret scanning. No production data mutation, credential rotation, webhook registration, database migration or deployment was performed by these review tests. Live IAM/storage policies, hosting/WAF settings, complete secret history, external-provider dashboards and a full browser penetration test are outside the verified evidence. The CSP deliberately leaves scripts/connections unrestricted to preserve existing media/payment functionality; it is not a claim of comprehensive XSS prevention. File signature checks reject obvious type confusion; they are not malware scanning.
